# 第 8 层：正确性、精度、性能与开发环境

[概念目录](../README.md) · [布局案例](layout-case.md)

## 三种证据

| 层面 | 关心什么 | 不能替代什么 |
|---|---|---|
| 功能正确性 | shape、轴、地址、mask、索引、边界与输出语义 | 编译成功不能证明数值正确 |
| 数值精度 | 与指定参考的误差、NaN/Inf、舍入与量化损失 | 数值接近不等于完整模型任务效果相同 |
| 性能 | 时延、吞吐、资源利用与等待 | CPU 数学验证不能证明 NPU 加速 |

先保持语义和输入一致，再比较实现的数值和耗时。

## 测试与调试名词

| 名词 | 最小解释 |
|---|---|
| Golden / Reference | 用于比较的可信参考实现；必须明确其输入和量化语义 |
| UT | 单元测试，常针对 Host 推导、校验或局部逻辑 |
| ST | 系统/集成层测试，覆盖实际执行链；具体目录命名以工程为准 |
| TTK | 本项目测试入口和用例体系中的名称；不能仅凭缩写猜测其完整能力 |
| aclnn Fuzz | 根据接口和用例约束构造、运行不同输入的测试机制；不是只生成任意随机数 |
| Ascend C Debug Tool / msDebug | 算子调试工具，具体命令与能力按环境版本核对 |
| Breakpoint / Call stack | 断点 / 调用栈，用于定位执行位置和调用关系 |
| OOB / 越界 | 地址超出合法范围，可能读错、写坏数据或报错 |
| Race / 同步错误 | 多阶段访问顺序不满足依赖，结果可能不稳定 |
| Regression / 回归 | 修改后重跑旧用例，检查既有路径是否被破坏 |
| Seed / Case | 随机种子 / 完整输入配置，使结果可复现 |
| atol / rtol | 绝对、相对容差；常检查 abs(actual-ref)≤atol+rtol*abs(ref) |
| MaxAbs / RMSE / RelativeL2 | 最大绝对误差、均方根误差、整体相对 L2 误差 |
| NaN / Inf | 非数 / 无穷；需要独立检查，不能仅看平均误差 |

量化测试有两种不同参考：与原始高精度输入比较用于衡量量化损失；与相同量化值、scale 及转换约定比较用于定位实现错误。[误差公式详解](../07-features/quantization.md)

## Cube bound、Vector bound 与其他瓶颈

| 名称 | 性能主要受什么限制 |
|---|---|
| Cube bound | 矩阵计算资源或相关计算效率 |
| Vector bound | 向量计算、指数、归约、转换等阶段 |
| Memory / Bandwidth bound | 数据搬运带宽、访存效率 |
| Synchronization bound | 阶段依赖、事件或缓冲区复用造成的等待 |
| Load imbalance | 核间工作不均衡，整体等待最慢的核 |

FLOPs 是运算次数；FLOP/s 是计算速率；带宽是每秒数据量。算得多不一定耗时最长，仍要除以实际有效处理速度。

在足够多块、搬运同步可忽略、两类资源充分交叠的简化模型中，稳态每块耗时约为 max(T_Cube,T_Vector)。它不是单块延迟公式，实际流水还存在启动、排空、阶段依赖和数据搬运。

**“Vector 阻塞在 scale”不是已证实的瓶颈诊断。** 应区分等待 scale 搬运、等待缓冲可用、量化计算耗时、scale 读写碎片化等原因。只有源码存在 Wait 不能证明 Vector 计算饱和。

## Profiling、时延与吞吐

Profiling 采集时间线、各阶段执行和等待等信息。Latency 是一次请求/算子完成时间；Throughput 是单位时间处理量。优化应固定 shape、dtype、mask、稀疏密度和版本，预热后多次测量，并说明同步点和计时范围。

减少访存、提高复用、调整 tile、双缓冲、模板化、改变分核都可能有收益，也有资源占用和复杂度代价；任何具体加速比例必须有测量依据。

## 工程环境和规范

| 名词 | 在学习中的定位 |
|---|---|
| Linux / WSL2 | 目标系统 / Windows 中的 Linux 环境；可练习普通开发，不自动具备 NPU |
| SSH / Remote IDE | 连接实际 Linux/NPU 开发机的入口 |
| Codespaces / Dev Container | 云端或容器化开发环境；是否有目标设备需另外确认 |
| Docker / Image | 隔离用户态依赖；不自动补齐宿主驱动与硬件 |
| CANN / Ascend C | 昇腾软件栈 / 算子编程体系 |
| torch_npu / Driver | 框架适配 / 设备驱动，需与目标软件环境配套 |
| clang-format / clang-tidy | 格式化 / 静态分析工具；检查范围和实际规则应读工程配置 |
| CI / Build / Test | 自动化检查 / 构建 / 行为验证；通过其中一项不等于全部通过 |
