# 00｜FA 零基础扫盲

## 1. 什么是“算子”？

模型可以看成一张计算图，里面每个明确的计算单元就是算子，例如 Add、MatMul、Softmax、LayerNorm。

同一个数学表达式可以有不同实现。算子开发关注的不只是“结果算对”，还包括：

- 在什么芯片上运行；
- 输入输出的数据类型、形状和排布；
- 如何分配并行任务；
- 数据放在哪一级存储；
- 如何减少搬运、等待和重复计算；
- 如何被 PyTorch 或其他框架调用。

因此，**算子 = 数学语义 + 接口契约 + 硬件实现 + 验证与交付**。

## 2. FA 是什么？

这里的 FA 指 FlashAttention。先看标准 Scaled Dot-Product Attention：

```text
S = Q × Kᵀ × scale
P = softmax(S + mask)
O = P × V
```

常见的 `scale = 1 / sqrt(d)`，其中 `d` 是每个注意力头的维度。

各张量的直觉：

| 张量 | 含义 | 常见形状（单头简化） |
|---|---|---|
| Q | 我正在查询什么 | [Nq, D] |
| K | 每个位置提供什么索引 | [Nk, D] |
| V | 每个位置真正携带的内容 | [Nk, Dv] |
| S | 每个 Query 对各 Key 的相关分数 | [Nq, Nk] |
| P | 归一化后的注意力权重 | [Nq, Nk] |
| O | 按权重汇总后的结果 | [Nq, Dv] |

当序列长度为 `N` 时，`S` 和 `P` 都可能达到 `N × N`。问题不仅是乘法多，更重要的是这些巨大中间结果可能在高带宽但远离计算单元的全局内存中反复读写。

## 3. FlashAttention 为什么快？

FA 的主线是 **IO-aware（关注数据搬运）**。

标准实现容易经历：

1. 算 `QKᵀ`；
2. 将大矩阵 `S` 写回全局内存；
3. 再读出做 Softmax；
4. 将 `P` 写回；
5. 再读出与 `V` 相乘。

FA 将 Q、K、V 分块搬入更靠近计算单元的片上存储，在块内完成矩阵乘、Softmax 更新和输出累加，避免完整 `N × N` 中间矩阵反复落到全局内存。

关键点：

- **Tiling**：大矩阵切成能放入片上存储的小块；
- **Fusion**：多个阶段在一个融合 Kernel 内衔接；
- **Online Softmax**：一边读取分块，一边维护全局 Softmax 所需统计量；
- **Recompute**：训练反向时有时宁愿重算，也不保存巨大的中间矩阵；
- **Pipeline / Double Buffer**：计算当前块时预取下一块，减少等待。

FA 并没有神奇地消除主要矩阵乘法；它主要减少不必要的全局内存访问，并改善硬件利用率。

## 4. Online Softmax 是什么？

普通稳定 Softmax 对一行分数 `x` 计算：

```text
m = max(x)
l = Σ exp(xᵢ - m)
softmax(xᵢ) = exp(xᵢ - m) / l
```

分块后，不能只对每一块分别做 Softmax 再拼接，因为每块的分母不同。Online Softmax 会维护：

- `m`：截至当前块的全局最大值；
- `l`：经过尺度修正后的指数和；
- `acc`：尚未最终除以 `l` 的输出累加值。

读到新块时，先计算新的最大值，再把“历史累加结果”和“当前块结果”变换到相同指数尺度后合并。最终 `O = acc / l`。

这件事必须理解清楚，因为它同时决定：

- 结果是否正确；
- 是否数值稳定；
- 分块之间如何传递状态；
- 输出累加使用什么精度。

## 5. 昇腾上的软件与硬件层次

初学时先形成下面这条链：

```text
PyTorch / MindSpore
        ↓ 框架适配或单算子调用
CANN 运行时与算子库
        ↓
Host 侧：算子定义、Shape 推导、Tiling、Kernel 启动
        ↓
Kernel 侧：Ascend C 代码
        ↓
AI Core：矩阵计算、向量计算、数据搬运与片上存储
```

你会反复遇到两类代码：

- **Host 侧**：根据输入 Shape、Layout、数据类型和硬件资源，决定如何切分任务并生成 Tiling 参数；
- **Kernel 侧**：每个 AI Core 按 Tiling 参数搬数据、计算和写回。

不要把 Host 侧理解成“业务 CPU 代码”，它是算子实现不可缺少的调度与参数准备部分。

## 6. 三个最重要的硬件直觉

### 6.1 搬运可能比计算更贵

理论 FLOPs 相同的两个实现，性能可能差很多。原因通常是数据从较远存储搬到计算单元的次数、粒度和等待时间不同。

### 6.2 片上空间小，所以必须分块

块太大放不下；块太小则矩阵计算效率低、循环和同步开销高。Tiling 本质上是在容量、并行度、复用率和计算效率之间找平衡。

### 6.3 矩阵与向量阶段特性不同

FA 同时包含：

- `QKᵀ`、`PV`：矩阵乘，适合矩阵计算单元；
- max、exp、sum、除法、mask：向量/归约计算；
- GM 与片上存储之间的数据搬运。

高性能实现需要让这些阶段正确衔接，并尽量重叠执行。

## 7. 一个 FA 算子需要处理哪些输入差异？

真正的工程实现远比公式复杂：

- Batch 数量；
- Query 头数、KV 头数（MHA/GQA/MQA）；
- Query 和 Key/Value 序列长度；
- Head Dim；
- 数据类型（FP16、BF16 等）；
- Layout（如 BSH、BNSD 等）；
- causal mask、padding mask、稀疏模式；
- 训练或推理；
- 变长序列；
- 对齐、尾块和空块；
- 芯片型号及其资源约束。

所以“能跑一个固定 Shape”只是实验，不等于完成一个可交付算子。

## 8. 正确性、精度与性能要分开看

### 正确性

- Shape 与索引是否正确；
- mask 语义是否正确；
- 是否越界；
- 是否漏算或重复计算；
- 特殊 Shape 是否可运行。

### 数值精度

- 与高精度参考实现的误差；
- FP16/BF16 输入、FP32 累加等策略；
- Softmax 是否溢出或下溢；
- 极端输入是否出现 NaN/Inf。

### 性能

- Kernel 耗时与吞吐；
- AI Core 并行是否均衡；
- 矩阵/向量/搬运单元是否有长时间空闲；
- GM 访问量；
- 流水线中是否存在同步和数据依赖造成的气泡。

一个错误实现可能“非常快”；一个正确实现也可能因为搬运过多而很慢。因此验证顺序必须是：**先正确，再精度，再性能**。

## 9. 初学者最常见的误区

1. 直接阅读完整 FA 工程，结果被模板和宏淹没；
2. 只背 API，不理解张量 Shape 和数据流；
3. 认为矩阵乘法算得快，整个算子就快；
4. 把每块 Softmax 后直接拼接；
5. 只测一个整齐 Shape，不测尾块、mask 和变长；
6. 只看相对误差，不检查 NaN/Inf 和极小值；
7. 没固定 CANN、芯片与框架版本就照抄代码；
8. 优化后只看一次耗时，没有稳定预热、重复测量和对照基线。

## 10. 你现在应该掌握的最小结论

学完本章，至少能说清：

- 算子开发为什么不等于写数学公式；
- Attention 的四步计算与各张量 Shape；
- 标准 Attention 的 `N × N` 中间矩阵为什么昂贵；
- FA 通过分块和融合减少了什么；
- Online Softmax 为什么是分块 FA 的关键；
- Host Tiling 与 Kernel 执行各自负责什么；
- 为什么正确性、精度和性能必须分阶段验证。
